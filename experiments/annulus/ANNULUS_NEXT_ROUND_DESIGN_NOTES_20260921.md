## 1. S6-R：等总量重分配（rSamplingDeficiency 与 rOptimizationFailure 的判别）

**为什么需要它。** 既有的采样探针全部改变了**资源总量**（密度 2× / 2.76×）或**抽签**（换 sample seed），而两个候选原因对「增加资源」的预测完全一致，对「换抽签」也没有分歧。唯一可能有识别力的操纵是：**总量不变、预算不变，只改分布**。

**设计要点（未冻结）：**

```text
总配置点数     1024        固定，与 r1 相同
训练预算       120000      固定，与 r1 相同
init / batch / sample   沿用 r1 的十个配对三元组，一个不改
唯一变化       把配置点从计数最高的格迁到计数最低的格，直至每格 >= 中位数
目标格的选法   机械规则：「该 seed 配置点数最少的格」——绝不写死 2,13
正控制         合成饥饿注入：人为把某个已知格抽稀，确认该设计能检出
```

**为什么必须是机械规则。** 写死 `2,13` 会把「我们已经知道哪个格出了问题」编进设计里，于是无论结果如何都只是在确认既有观测。目标格必须由每个 seed 自己的配置点分布决定。

**一个必须提前堵死的近亲陷阱。** 「固定点集、只提 `2,13` 那 5 个点的 loss 权重」看起来是同一个干预的更省钱版本，实际违规：`lossWeights` 是 `rOptimizationFailure` 定义里的变量（"loss weighting"），动它等于动对方的因子，两因会同时存活。

**它不能做的事。** 即使 S6-R 给出干净结果，它也只处理这**一对**原因；`rReferenceDefect`、`rSingularityTreatment`、`rCapacityLimit` 三项排除义务一分不减。

**成本：** 10 个配对 seed × 120k 步 + 1 次正控制 ≈ 3.6–4.0 GPU 小时。

**为何不现在冻结：** 真正绑住命名动作的是另外三项未排除。在它们清掉之前，这道二选一的边际治理收益是零；而先跑它，等于先付最贵的账。

## 2. R3 的替代仪器（rReferenceDefect）

**R3 的规范缺陷（可事前陈述，不依赖任何已看到的结果）：** R3 的阈值是**被诊断对象自身**的函数——「参考在热点单元的误差 ≤ 模型在该单元误差的 1/10」。被诊断的模型越差，判据越容易通过；模型越好，判据越难通过。一个随被测对象漂移的阈值没有固定分辨力。

**替代仪器必须满足的性质（未冻结）：**

1. **能失败。** 存在一个可构造的世界，在那里这台仪器给出 FAIL。`refinement_diagnostic` 一旦通过，「测 FDM 精度」这一族的答案就已冻结——那不是判据，是追认。
2. **注入式。** 给参考解注入一个已知幅度的缺陷，确认下游的 ACA-9 会动；再在真实参考上测量，确认它没动。
3. **绑定到被裁决的那条路径。** 审计必须覆盖**裁决** ACA-9 的模块（`gates_annulus.external_checks`），而不只是**计算**它的模块——这正是 R1 第一版栽的地方。

**R1 的现状必须一并处理。** 修复后的审计（43 个模块）给出 `['pinn.experiments.gates', 'pinn.experiments_annulus.gates_annulus']`，故按 R1 原判据现在 **FAIL**。实测 FDM 只用于 Gate 2 与 PH7、不参与 ACA-9 的计算，所以更精确的命题是「**ACA-9 的数值**由解析解算出，其调用路径不含 FDM；但**裁决它的模块**确实 import 了 FDM（用于别的 Gate）」。下一版判据必须按这个更精确的命题来写，而不是按「没有任何模块碰过 FDM」。

**R4 已经不需要重新设计**：符号修好、改为按残差容差迭代之后，预注册的**原判据**直接通过（观测阶 0.0100，远在 [1.8, 2.2] 之外）。保留原判据。

## 3. 奇异性复检（rSingularityTreatment）——明确推迟，不给期限

**「最差单元位置」这一族判据整体退役。** α = 0.01 单侧精确二项检验对 H0: p ≥ 0.5 的拒绝域：n ≤ 6 为**空集**、n = 10 恰为 `{0}`、n = 20 为 k ≤ 4、n = 30 为 k ≤ 8。也就是说「前瞻性写一个 G2′ 二项检验」在数学上**就是 G2**，只是换了个 n；若按密度分臂、每臂 n = 5，它连拒绝域都没有。换个更花哨的计数统计量不会改变这一点。

**将来真要排除，必须走干预式（未冻结）：**

```text
A 臂   现行解析 u*
B 臂   u* + 事前冻结幅度阶梯的真 r^(2/3) 内圆奇异项，f 重算并通过 C1 一致性检验
控制   同域、同流水线、同预算、同配置点集 —— 尤其是同配置点集
产出   检出下限 A_min，以及有界结论「仅对强度 >= A_min 的奇异性成立排除」
必填   controlExecuted、A_min
```

**为什么绝不能挂到 S6-R 上。** S6-R 按设计操纵配置点的空间分布，而配置点分布正是任何空间统计量的混杂变量。把奇异性复检挂上去，保证两个原因同时存活。

**一条必须写进下一份预注册的教训。** G3 的冻结文本（`r^(2/3)` 场）与它自己的通过条件（热点落在 bin 0）自相矛盾：实测字面的 `d^(+2/3)` 场热点落在 `3,8`（贴外圆）。任何正控制在冻结之前，必须先验证**它自己能通过自己的通过条件**。

## 4. 容量阶梯（rCapacityLimit）

**它现在是一项真实的未排除义务**，不再是记账问题。`FACTOR_CONTROL = {"capacity": "architecture"}`、`MIN_INTERVENTION_LEVELS = 3`、`MIN_INTERVENTION_SEEDS = 3`。

**设计要点（未冻结）：**

```text
变化的控制   architecture，且只有它
档位         >= 3 档宽度或深度（例如 4x48 / 4x64 / 4x96），r1 的 4x64 必须是其中一档
每档 seed    >= 3
冻结不变     sampling、optimizer、lrSchedule、lossWeights、trainingBudget、spec、reference、seedProtocol
```

**必须提前想清楚的一件事：** `trainingBudget` 在 `INTERVENTION_CONTROLS` 里是必须冻结项，所以容量阶梯只能在**单一**预算下做。选 120k（r1 的预算）还是 180k（B\*），是一个会影响结论含义的选择，必须在看到任何结果之前裁定并写明理由。

**成本：** 3 档 × 3 seed × 120k 步 ≈ 3.2 GPU 小时（取 3 seed 下限）；若按十个配对 seed 做满，≈ 10.6 GPU 小时。

**我的预期与形式状态是两回事：** 我个人预期诚实的容量阶梯会把 `rCapacityLimit` 干净排除——`B* = 180k` 已经表明同一容量能达到判据。但预期不是证据，这项义务照样要还。

## 5. 顺序建议（供裁决，不具约束力）

若目标是把 Root Cause 从 `UNDETERMINED` 推出去，四项未排除里**最便宜且最可能成功**的是容量阶梯（§4，约 3.2 GPU 小时，设计毫无争议）；其次是 R3 的替代仪器（§2，几乎零 GPU，主要是设计工作）；最贵且最可能仍然分不开的是 S6-R（§1）；奇异性（§3）成本最高、设计最难，且它是唯一一个连「该测什么」都还没定下来的。

但这只是成本排序。**是否要把 Root Cause 推出去，本身就是一个尚未裁决的问题**——`rUndetermined` 的 DiagnosisRecord 已被实测证明写得出来，它会把状态迁到 `STOPPED_THE_LINE`，而那可能才是对这轮实验最诚实的归宿。
