# 科研候选版人工验收故障修复

人工验收报告了聊天调用失败、科研任务停在草案和界面增强加载失败。本次修复保留原验收失败记录，不将连接恢复视为科学验收通过。

## 原因与修复

1. `DesktopUI._inject_backend` 要求注入表达式返回布尔 `true`。科研面板是合并脚本的最后一个表达式，原先没有返回值，导致已部分加载的界面被判为失败。现在首次加载和重复加载均返回成功；核心未加载、版本不符或来源不符时仍返回失败。
2. 受影响安装的 DeepSeek 配置使用了服务端不支持的 API 模型名。真实 `/models` 请求成功，错误模型请求返回 HTTP 400。这与密钥未保存不同。修正安装内的模型名并通过原生模型服务更新会话绑定后，真实聊天和草拟请求成功。修正前备份加密配置，不把凭据、个人配置或机器记录写入 Git。
3. 原任务只有创建事件，没有草案。验证页仅显示 `DRAFT`，缺少继续入口。创建任务现在接着生成草案；失败时保留任务、给出分类错误和重试按钮。草案、模型已确认和待运行确认的状态都有明确的下一步导航。

草拟服务区分不支持的模型、鉴权失败、限流、服务错误、网络错误、超时和格式错误；不将供应商响应体或密钥返回界面。

## 回归与验收边界

- JavaScript 运行测试覆盖注入确认、重复加载、来源和核心初始化边界。
- 界面运行测试覆盖创建后草拟失败仍保留任务、具体错误提示、验证页返回草拟页及不触发人工确认。
- 服务测试覆盖 HTTP 错误分类及响应体不反射。
- 实际提供方连接、应用后端聊天和用户任务草拟的收据放在机器专属的 `docs/manual-acceptance-evidence/research-v1-repair/`，不属于源代码。
- 原生 WebView2 人工点击、正式运行确认、训练、独立复现及 C2 均单独验收。单元测试、HTTP 成功或完成打包不能替代这些证据。

## 升级与回退

从干净提交构建候选包，通过 `tools/deploy_release.ps1` 的事务部署替换候选安装的发布文件，保留 `user/`、科研环境、任务和历史会话。安装内科学源码快照同步到对应提交；未批准运行的任务不能获得批准记录。

部署生成安装目录下的 `.leo-rollback-*` 备份，具体名称以部署收据为准。回退时关闭候选应用，从该备份恢复收据列出的发布文件，并把科学源码恢复到之前记录的提交。不要覆盖整个 `user/` 或其他安装。模型配置修复的加密备份单独保存；回滚代码不要求恢复那个已经确认无效的模型名。
