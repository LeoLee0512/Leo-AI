# Leo 自有科研工作台

## 用户目标与验收范围

用户反馈：进入 Leo AI Studio 时先出现 OpenAI4S 的前端，界面杂乱，科研草案像一份没有层次的文本。目标是大幅替换日常界面并重塑视觉，同时保持聊天、模型、历史与科学任务可用。

验收必须检查真实安装版首次进入、聊天与模型选择、历史重开、科研任务视图、设置以及高级计算入口。静态测试与浏览器夹具只能证明对应范围，不能代替原生 WebView2 和真实后端验证。

## 实现

- 默认导航直接加载 `workbench.html`。页面、样式和脚本由 Leo 提供，不先请求上游 HTML 再等待换肤，因此普通入口不存在上游首屏切换阶段。
- 2026-09-26 起与启动页共用淡墨浓秋配色（用户选定方案 A）：暖纸底、墨褐侧栏、朱砂主色，首屏复用启动页的淡墨树；秋香、竹青、朱砂、墨灰分别表示探索性、已验证、精度声明、不可下结论，黛蓝表示计算。跟随已保存主题与系统暗色；窄窗口与减少动态效果偏好有对应布局。原深绿配色停用。
- 本机 `WorkbenchGateway` 只接受预定义操作，把请求转交给已认证的回环后端。HTML 不包含后端凭据，模型内容作为文本渲染。
- 历史读取、分页、重命名、项目、模型选择、消息发送和按执行身份停止沿用后端记录；历史隐藏状态取自 Leo 自有账本。
- 科研面板沿用原任务服务、证据校验与原生人工确认；界面草拟不会授予任何科学执行权限。
- 「笔记本与计算」是 Leo 自有的只读视图：经本机网关读取会话的执行记录、内核状态与产物，图片与文本以内联方式预览，只能预览本会话登记的产物。界面不再有任何进入上游页面的入口（原「高级工作区」入口与其导航函数已移除）。上游后端、源码与许可、署名保留。

## 发布与验证

新 HTML/CSS/JS 和科研面板原文件均纳入构建、部署、来源登记与大小检查。运行环境仍不向桌面壳安装 Torch。

实际机器证据写入 `docs/manual-acceptance-evidence/workbench/`。`tests/fixtures/workbench-preview.js` 是明确标记的离线界面夹具，不进入发布包，不产生人工审批、科研结果或 Claim。
